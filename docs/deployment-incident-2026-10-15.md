# 배포 안정화 기록 (2026-10-15)

## 문제 상황

- 운영 주소 `https://ppodeuk-owner.vercel.app/login`에서 로그인 후 홈과 매장 관리가 오류 화면으로 바뀌고, 매출 관리는 무한 로딩됐다.
- 390px 모바일 화면에서 문서 폭이 435px까지 늘어나 가로 스크롤이 생겼다.

## 원인 찾기

1. 홈·매출·매장 조회가 공통 운영 API에 의존하고 프런트 제한 시간은 5초였다.
2. 운영 API는 콜드 스타트 지연과 데이터 API HTTP 500을 함께 보였다.
3. 기존 로컬 데모 작업은 로그인, 홈, 매출 일부만 가로채 관리 상세 화면은 실 API로 빠졌다.
4. 모바일 오버플로는 384px 고정 입력 폭, 256px 고정 사이드바, 가로 배치된 관리 레이아웃이 합쳐져 발생했다.

## 해결 방법

- Vercel이 항상 `npm run build:demo`를 사용하도록 배포 설정과 `.env.demo`를 추가했다.
- 홈, 매장 목록/상세, 베이 목록/예약 내역, 매출/매출액과 주요 변경 요청까지 데모 핸들러 범위를 확장했다.
- 사이드바와 핵심 관리 화면을 모바일에서는 세로 배치하고 데스크톱에서만 기존 고정 사이드바를 사용하도록 변경했다.
- 로그인 입력은 `max-width`를 유지하되 작은 화면에서는 부모 폭을 넘지 않도록 조정했다.

## 결과

- 제출용 사이트의 로그인 이후 핵심 조회 흐름이 운영 API 상태와 분리됐다.
- 홈, 매출, 매장 관리, 베이 예약 내역을 일관된 샘플 데이터로 시연할 수 있다.
- 작은 화면에서 공통 고정 폭과 가로 레이아웃으로 발생하던 오버플로 경로를 제거했다.

## 검증과 성과

- 기존 변경 포함 테스트: 6개 파일, 16개 테스트 통과
- ESLint: 경고 0개
- 일반 프로덕션 빌드와 데모 프로덕션 빌드: 성공
- 실제 브라우저 클릭 흐름: 로그인 → 홈 → 매출 관리 → 매장 관리 → 매장 상세 → 베이 예약 내역 성공
- 데스크톱 홈 이미지 5개와 모바일 예약 내역 이미지 3개 모두 로드 완료(`naturalWidth > 0`)
- 390px 로그인과 베이 예약 내역에서 `scrollWidth = clientWidth = 390` 확인
- 서비스 워커 등록이 지연돼도 2초 뒤 앱을 렌더링하도록 복구 경로를 추가해 흰 화면을 방지했다.

## 후속 개선

- 운영 전용 배포가 필요하면 Vercel 프로젝트를 데모와 실 API 환경으로 분리한다.
- Railway 로그 접근 권한을 확보해 Owner 로그인과 데이터 조회 500의 서버 예외를 확인한다.
